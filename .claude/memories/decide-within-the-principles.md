# Decide within the principles

The user leaves to Claude every choice that the production principles and the memories can settle. What the user asks of the work is that it follows them; how it does so is Claude's to decide. It is the user's rule.

**Why:** No reason comes with it. Claude's interpretation: the principles and the memories are there so that the user need not rule on each choice, and a question that they already answer costs the user's time.

**How to apply:** When a draft breaks a principle, correct it and report what changed; do not lay the correction out as options for the user to pick from. Cutting, splitting, reordering, and rewording scenes are Claude's to do when a principle decides them. A choice that the user has not confirmed goes into the production's subject memory as Claude's, as in [The society film's subject](society-film-subject.md).

Claude's interpretation, which the user has not confirmed:

- The rule holds for every production (see [The repo is a media factory](the-repo-is-a-media-factory.md)), and for a piece of work from its start through its commit, its push, and the watch on its runs (see [Every run is watched](every-run-is-watched.md)).
- It does not reach what a memory keeps for the user: the mark that a script is ready (see [No video before the script is ready](no-video-before-the-script-is-ready.md)), and the audience, look, voice, music, and length of a new production.
- Releasing a film is not a choice to make: the `productions` workflow releases the film in the run that renders it, per [Render in GitHub workflows](render-in-github-workflows.md). The rule does not reach an action that cannot be undone and that no workflow does, such as deleting a release; that waits for the user's word.
